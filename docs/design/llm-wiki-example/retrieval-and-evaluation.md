# 从检索到销售回复的示例

纯虚构、静态说明；不是实际运行日志，不执行模型或 CRM 工具。

## 销售的问题

“星桥客户想一万元、10 月 9 日上线。帮我判断能不能答应，并拟一条回复。”

## 系统应读取的材料

先从当前可信登录身份解析组织和已选客户／商机／会话，再读取：

1. [客户原话 017](sources.md#src-customer-017)
2. [当前价格 v3](sources.md#src-price-003) 与它替代的[历史价格 v2](sources.md#src-price-002)
3. [交付政策](sources.md#src-delivery-002)
4. [该项目内部回复](sources.md#src-internal-008)
5. [本销售已经承诺的更新期限](sources.md#src-rep-019)
6. 真实系统中还要读取客户最新状态、现有报价、发送限制和已有待审草稿；本样例没有这些实时数据

授权应在检索前生效：组织匹配、人员可见范围、Agent 已批准来源集合、客户／项目范围、发布状态和有效期。不能先把所有客户资料发给模型再靠 prompt 隐藏不该引用的部分。

建议的单项证据记录包含 sourceId、业务 revision、索引 revision、chunk／anchor、原文片段、contentHash、observedAt、validFrom／validTo、来源负责人和授权范围。这里是目标字段说明，尚非当前数据库契约；真实值由存储和工具产生，不能让模型自己填写认证或权限事实。

## 可接受的助手答复

> 现在还不能直接答应。当前适用标准价是 CNY 12,000；客户的一万元请求约低 16.67%，需要商务负责人对本次报价批准。10 月 9 日只是客户目标，内部目前只有附条件的 10 月 12 日暂定意见，也不能承诺。你已经答应在 10 月 2 日 15:00 前更新确认进展。建议先请求价格和排期确认，并准备一条不承诺金额与日期的回复。

依据分别链接[当前价格](product-and-pricing.md#当前适用价格)、[折扣权限](product-and-pricing.md#折扣权限)、[内部暂定信息](sources.md#src-internal-008)、[销售承诺](sources.md#src-rep-019)。

可编辑客户草稿：

> 收到，您的预算和 10 月 9 日上线目标我都记下了。我正在确认这次服务范围、价格和可安排的上线日期，会按约在明天下午 3 点前向您更新进展。

这段“明天”只对示例生成时间 2026-10-01 09:30+08:00 成立。延后发送必须重算相对日期并重新审阅，或使用明确的 10 月 2 日。草稿没有发送，也没有因为生成它而获得发送批准。

## 如何显示不一致

- **旧价与新价**：同一标准包、不同生效期。按适用日期解释 v2 已替代，不把它当作同权威冲突。
- **客户日期与内部日期**：一个是客户目标，一个是暂定意见，不能二选一当作承诺。
- **两个仍有效的批准价格**：没有明确适用范围或替代关系时显示冲突，找资料负责人确认，不能按检索分数投票。
- **同一政策两个段落**：先看 chunk 与命题，不因摘录字符串不同就报矛盾。

## 来源更新之后

假设价格 v4 发布。系统应找出引用 v3 的产品页、异议页和仍待审的草稿，生成差异说明，并按照业务规则重新检查这些草稿。已经发送的内容保留当时版本，不能把历史悄悄改成“从来就是 v4”。客户已签订单应按订单约定单独判断。

客户删除、组织切换、员工撤权、知识来源撤权也必须影响缓存与派生摘要。纯 Markdown 文件无法实现这些动作。

## 最小离线验收集

| 输入变化                           | 预期结果                             |
| ---------------------------------- | ------------------------------------ |
| 同时检索出价格 v2 与 v3            | 新报价引用 v3，说明 v2 已替代        |
| 删除有效价格来源                   | 明确价格缺失，不以旧价猜测           |
| 仅提供客户原话                     | 把预算／时间列为请求，不当作双方承诺 |
| 内部回复仍有“暂定”                 | 不产生确定交期                       |
| 客户回复“收到”                     | 记录回复，不宣布接受条款             |
| 商务批准变成无权限人员的意见       | 不视为折扣批准                       |
| 两名专家读到不同有效版本           | 主 Agent 重查并说明差异              |
| 同文档不同段落都有效               | 可合并证据，不误报矛盾               |
| 查询属于另一个客户                 | 不返回星桥承诺页或原消息             |
| 审批后修改收件人／金额／日期／正文 | 旧批准失效，要求审核新版本           |
| 新客户消息在发送前到达             | 重新校验上下文并说明冲突             |
| 发送结果未知                       | 先核对账本，不自动重发               |

这些是期望行为和测试设计，不是已经执行通过的测试。落地后应分别报告离线、数据库、浏览器与真实渠道的验证结果。
